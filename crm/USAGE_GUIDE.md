# PEPTIVANTA CRM 新手使用说明

## 适用对象

业务员、销售组长、管理员。

## 核心原则

- 客户负责人以实际 WhatsApp 业务员为准。
- 销售阶段表示客户当前进度，S/A/B/C/D 表示客户优先级，两者不是一回事。
- 每次有效沟通必须记录：本次做了什么、客户反馈、下一步动作、下次跟进日期。
- “已成交 / 待付款 / 无效”等跟进结果会联动销售阶段和标签。
- 订单付款、物流、Tracking 不能只保留在 WhatsApp 聊天中，应同步到 CRM。

## 新增客户

1. 点击右上角“＋ 新增客户”。
2. 填写客户姓名、国家、WhatsApp、主要产品、客户类型、负责人。
3. 负责人应与实际跟客户沟通的业务员一致。
4. 可增加价格敏感、COA关注、批量采购、长期采购等特征标签。
5. 保存后客户进入客户工作台和销售管道。

### 截图识别

在新增客户中切换到“截图识别”，上传或粘贴 WhatsApp 截图。系统只做预填，保存前必须人工确认姓名、国家、号码、产品和规格。

## 客户工作台

推荐流程：

`筛选客户 → 选中客户 → 查看最近跟进 → 处理客户 → 保存跟进结果 → 继续下一位`

工作台可按跟进时间、客户类型、客户等级、销售阶段和负责人筛选。详情窗口左右切换会跟随当前筛选结果。

## 客户详情

快速双击客户卡片，或点击“打开客户 / 详情”进入客户处理窗口。

可以直接：

- 编辑客户资料
- 修改负责人、销售组、产品、等级、阶段、标签、备注
- 记录跟进
- 查看完整跟进历史
- 左右切换当前客户序列

## 合格的跟进记录

### 本次做了什么 / 发了什么

只记录事实。例如：

`发送 Tirzepatide 10mg 报价和 COA，并确认首批数量。`

### 客户反馈 / 原话

例如：

`价格可以接受，但需要和合伙人确认数量，预计明天回复。`

### 当前主要阻力

例如：价格、MOQ、规格、COA/检测文件、物流、付款、竞争供应商。

### 下一步动作

必须具体。例如：

`明天下午确认数量；确认后发送最终 PI 和付款信息。`

不要只写“已跟进”“客户考虑中”。

## 跟进结果联动

- 继续跟进：保留当前阶段，增加“跟进中”。
- 等待客户：增加“等客户回复”。
- 待付款：阶段进入“待付款”，增加“待付款”。
- 已成交：阶段进入“已付款/履约”，增加“已成交”，清理报价后未回复、待付款等过期标签。
- 暂缓：增加“暂缓”。
- 无效：等级改为 D，增加“无效客户”。

## 销售管道

主流程：

`新询盘 → 已首次回复 → 需求确认中 → 已发资料 → 已报价 → 议价中 → 待付款 → 已付款/履约 → 待复购/复购`

拖动管道只改变销售阶段，不应改变负责人。

## 订单管理

成交后持续维护：

- 客户
- 负责人
- 产品
- 销售金额
- 成本
- 付款状态
- 物流状态
- Tracking
- 订单日期

订单可通过“编辑”按钮修改。

## 销售组

美国和加拿大统一归入北美组，不再拆分为两个销售组。

## 权限

权限分为两层：

1. 功能权限
2. 数据范围

例如普通销售可以有客户编辑权限，但数据范围仅限本人客户。

当前版本的权限仍属于前端业务模型。未接服务端登录鉴权前，不应视为真正的数据隔离。

## 每日推荐工作流程

1. 处理逾期跟进。
2. 处理今日必须跟进。
3. 录入当天 WhatsApp 新客户。
4. 推进已报价和待付款客户。
5. 更新订单、物流和 Tracking。
6. 确保当天处理过的客户都有下一次跟进日期。
7. 导出数据备份。

## 数据备份

当前数据主要保存在浏览器本地。清理浏览器数据、换电脑、使用无痕模式都可能导致数据不可见。

正式使用期间建议每天至少导出一次 CRM 备份。

## 当前可正式使用的范围

当前版本可以作为单机 / 单浏览器 CRM 正式投入使用。

如果需要多人、多电脑同时协作，需要下一阶段接入：

- Cloudflare D1 数据库
- 正式登录系统
- 服务端权限控制
- 跨设备数据同步
