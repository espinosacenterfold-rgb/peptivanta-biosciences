PEPTIVANTA CRM 新手使用说明

这份说明按业务员实际工作顺序编写。新员工建议先完整看一遍，再开始录入真实客户。

返回 CRM直接看每日流程

1. 第一次使用先理解 4 个核心概念

负责人：管理员给业务员设置的备注名，例如 Sophia、Kevin。客户由谁的 WhatsApp 跟进，就归谁负责。

销售阶段：表示客户现在走到哪里，例如新询盘、需求确认、已报价、待付款、已成交/履约、复购。

客户等级：S / A / B / C / D 表示客户价值和优先级，不等于销售阶段。

跟进记录：每次和客户发生有效沟通，都要记录“做了什么、客户怎么回复、下一步是什么、什么时候再跟”。

不要把标签当备注乱写。销售阶段、跟进结果和部分标签会自动联动。人工标签主要用于补充客户特征，例如“价格敏感、文件关注、大额潜客、物流敏感”。

2. 新增客户

点击右上角“＋ 新增客户”新客户第一次进入 WhatsApp 后就可以建档，不要等到报价后才录入。
优先填写必要信息客户姓名、国家、WhatsApp、主要产品、客户类型、负责人。金额不确定时可以先填 0。
选择负责人和销售组负责人要和实际跟客户沟通的 WhatsApp 业务员一致。
补充客户特征例如价格敏感、COA关注、批量采购、长期采购、样品咨询。
保存保存后客户会进入客户工作台和销售管道。

截图辅助建档

新增客户时切到“截图识别”，上传或粘贴 WhatsApp 截图。系统会尝试提取姓名、号码、国家、产品、规格、客户类型和关键词。

识别结果只用于预填，必须人工检查后再保存。尤其是姓名、国家、+1 区号（美国/加拿大）和产品规格。

3. 客户工作台怎么用

客户工作台是每天最主要的页面。左侧是当前客户序列，右侧是选中客户的上下文和跟进建议。

筛选客户 → 选中客户 → 查看最近跟进 → 处理客户 → 记录结果 → 继续下一个客户
“跟进建议”是辅助判断，不代替业务员判断。真正有效的信息以客户最近一次反馈、订单状态和历史跟进为准。

4. 客户详情与编辑

在客户卡片上快速双击，或点击“打开客户 / 详情”，会进入居中的客户处理窗口。

详情窗口可以左右切换客户。左右顺序会跟随你当前的筛选结果，不会跳到筛选范围外。

需要修改客户资料时点击“编辑客户”；需要跟进时直接点击“记录跟进 / 直接跟进”。

客户换业务员时要修改“负责人”，不要只改备注。负责人决定后续客户归属和数据统计。

5. 一条合格的跟进记录怎么写

字段应该写什么示例
本次做了什么 / 发了什么只写本次实际动作发送 Tirzepatide 10mg 报价和 COA，并确认首批数量。
客户反馈 / 原话客户实际回复、顾虑或决定价格可以接受，但需要和合伙人确认数量，明天回复。
当前主要阻力本次成交推进最主要的问题价格 / MOQ / 文件 / 物流 / 付款 / 竞争供应商
下一步动作下一次要完成的具体动作明天下午确认数量；确认后发送最终 PI 和付款信息。
下次跟进日期明确到日期2026-08-24
不要只写“已跟进”“问了客户”“客户考虑中”。这种记录下一位接手的人无法继续工作。

6. 跟进结果和标签如何联动

选择结果系统动作什么时候用
继续跟进保留当前阶段，增加“跟进中”客户仍有推进空间
等待客户增加“等客户回复”已经把问题/资料发给客户，等回复
待付款阶段进入“待付款”，标签同步订单已经基本确认，只差付款
已成交阶段进入“已付款/履约”，增加“已成交”，清理报价后未回复等旧标签确认成交/付款后
暂缓增加“暂缓”，保留客户客户明确表示晚些时间再推进
无效等级变为 D，增加“无效客户”明确无效、错误询盘等
原则：跟进结果必须和真实业务状态一致。不要为了让工作台好看而把客户提前标成“已成交”。

7. 销售管道

销售管道按阶段展示客户。卡片可以拖动改变阶段。

建议的主流程：

新询盘 → 已首次回复 → 需求确认中 → 已发资料 → 已报价 → 议价中 → 待付款 → 已付款/履约 → 待复购/复购
拖动销售管道只改变销售阶段，不应该改变负责人。

8. 订单管理

客户成交后检查订单核对客户、负责人、产品和金额。
更新付款状态待付款、部分付款、已付款、已退款。
更新物流状态待发货、备货中、已发货、运输中、已签收、异常。
填写 Tracking拿到物流单号后及时补充。
需要修改时点“编辑”金额、成本、产品、负责人、物流和日期均以实际订单为准。

9. 筛选客户

工作台支持按跟进时效、客户类型、客户等级、销售阶段、负责人和搜索关键词筛选。

常用筛选方式：
今日需跟进已逾期3天+未跟进S/A重点已报价负责人

筛选后打开客户详情，左右切换只在当前筛选出来的客户序列中进行。

10. 账号、销售组和权限

客户归属显示业务员备注名，例如 Sophia、Kevin，不显示“私海”。

美国和加拿大业务统一归为北美组。其他市场可按实际组织继续设置。

权限分为两层：功能权限和数据范围。例如普通销售可以有客户编辑权限，但数据范围只允许本人客户。

当前版本的账号/权限仍是前端业务模型。在没有服务端登录鉴权之前，它不能真正阻止另一台电脑读取数据。

11. 数据备份

右上角“导出数据”会导出当前 CRM 数据备份文件。

建议正式使用后每天至少导出一次，重要成交日额外导出一次。

清理浏览器数据、更换浏览器、换电脑或使用无痕模式，都可能导致当前本地数据不可见。未接数据库前必须重视备份。

12. 业务员每天推荐工作流程

先处理“逾期跟进”先清理已经超过计划日期的客户。
再处理“今日必须跟进”按客户等级和机会金额排序。
检查新进客户当天 WhatsApp 新粉及时建档并完成首次有效沟通。
推进已报价和待付款这两类通常距离成交最近。
更新订单和物流付款、Tracking、签收状态不要只留在 WhatsApp 聊天里。
下班前检查确保今天处理过的客户都有完整跟进记录和下一次跟进日期。
导出备份当前本地版正式使用期间建议每日备份。

13. 正式使用前注意事项

  • 真实客户建档后，负责人必须与实际 WhatsApp 业务员一致。
  • 每次有效沟通都记录跟进，不依赖业务员个人记忆。
  • “已成交、待付款、无效”等结果按实际情况选择，系统会联动阶段和标签。
  • 订单付款、物流和 Tracking 要持续更新到签收。
  • 当前数据保存在当前浏览器，本地版必须定期导出备份。
  • 如果开始多人、多电脑正式协作，需要升级到 Cloudflare D1 + 正式登录鉴权后再开放子账号。
当前版本可以作为单机 / 单浏览器业务 CRM 开始正式使用。如果现阶段主要由一个管理员或固定一台电脑维护客户，这套流程已经可以落地。多人同时使用前，再完成数据库和服务端权限升级。
